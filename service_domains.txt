# Curated service-domain list — hosts hidden from the public tier lists
# (04-lifecycle §"service"). Criterion (2026-08-01, revised): a domain is
# hidden ONLY if an end-user client never names it directly. IPv6-only
# viability is the mission, so everything a client connects to stays visible —
# content CDNs (cloudfront.net, fbcdn.net), API/SDK/app backends (googleapis,
# tiktokv.com), OS/update/auth/connectivity endpoints (windowsupdate.com,
# msftconnecttest.com), app-hosting suffixes (github.io), device/IoT backends,
# PKI and public-resolver endpoints.
#
# Hidden here:
#  1. DNS/registry/nameserver zones and parking — resolvers contact these, not
#     clients; each site's dependency on them is already measured by its `ns`
#     dimension. Special-use names too (ipv4only.arpa is v4-only by RFC 7050).
#  2. CNAME/load-balancer layers (msedge.net, edgekey.net) — clients resolve
#     through them but never name them; the reachability they gate is measured
#     on the domains that CNAME onto them.
#  3. Web ad/tracking/analytics/consent serving — clients fetch them, but the
#     impact is carried by each embedding site's resources dimension, and their
#     failure is not user-felt. Includes rotating ad-blocker-evasion aliases
#     (Statsig's prodregistryv2.org etc.), which have zero shame value.
#
# Curation source: full review of the Tranco top-1000 with per-host content
# probes and ownership research for every ambiguous name. Unidentified hosts
# stay visible (needs-info), they are not added here on suspicion.
#
# Apply:  v6ctl disable --service-list service_domains.txt   (idempotent)
# Revert: v6ctl enable <host>                                (per host)
